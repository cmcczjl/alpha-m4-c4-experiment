# 研究报告：加密货币跨交易所套利（Statistical Arbitrage）

## 背景
- **加密货币市场** 24/7 运行，流动性在不同交易所之间分布不均。
- **价格差**（Spread）在高波动时段会出现短暂的偏离，为套利提供机会。
- 常见的套利类型：
  1. **跨交易所现货套利**（买低卖高）。
  2. **跨品种套利**（例如 BTC/ETH 价差）。
  3. **期现套利**（现货与永续合约之间的价差）。

## 数据来源建议
| 数据类型 | 推荐 API / 数据源 | 说明 |
|----------|-------------------|------|
| 现货价格 | Binance, Coinbase Pro, Kraken, OKX | 提供深度、成交量、历史 K 线 |
| 永续合约价格 | Binance Futures, Bybit, FTX (已关闭) | 永续合约的标记价格与指数价格的差异 |
| 交易费用 | 各交易所公开的费率表 | 包括 maker/taker 手续费、提现费 |
| 跨链转账时间 | 各链官方文档 | 评估资金调度的延迟 |

## 套利模型概念

1. **价格差阈值**  
   - 计算同一资产在两个交易所的 **加权中位价**（考虑深度）。  
   - 当价差 > `threshold = fee_total + risk_buffer` 时触发套利。

2. **资金调度**  
   - 采用 **预置双向持仓**（在两个交易所同时持有等额资产），减少转账延迟导致的滑点风险。  
   - 若资金不足，可使用 **闪电贷**（如 Aave）进行瞬时放大交易。

3. **风险控制**  
   - **最大持仓比例**：不超过总资产的 30%。  
   - **单笔交易最大亏损**：设置止损为 0.5% 的预期利润。  
   - **监控网络拥堵**：在链拥堵时自动暂停套利。

## 初步实现路线

| 步骤 | 说明 | 产出 |
|------|------|------|
| 1. 数据抓取 | 使用 CCXT 库实时获取 Binance 与 Kraken 的 BTC/USD、ETH/USD 深度 | `work/fetch_price.py` |
| 2. 差价计算 | 对每个时间点计算加权价差，记录超过阈值的事件 | `data/spread_log.csv` |
| 3. 回测框架 | 基于历史深度数据回测上述逻辑，评估年化收益、最大回撤 | `work/backtest_arbitrage.py` |
| 4. 实时执行 | 将回测验证通过的策略部署为监控脚本，使用 WebSocket 低延迟下单 | `work/runner.py` |
| 5. 监控与报警 | 实时记录收益、费用、异常情况，发送 Telegram/Discord 通知 | `work/monitor.py` |

## 关键技术栈

- **Python 3.11+**
- **CCXT**：统一的加密货币交易所 API 接口
- **Pandas / NumPy**：数据处理与统计
- **Backtrader / Zipline**：回测框架（可自行实现轻量版）
- **WebSocket**：实时行情订阅
- **Docker**：容器化部署，确保环境一致性

## 预期挑战

1. **网络延迟**：跨交易所下单的网络往返时间可能导致套利窗口瞬间消失。  
2. **手续费波动**：高频交易时手续费占比显著，需要动态获取最新费率。  
3. **资金安全**：在多个交易所持仓增加了被盗风险，需要使用硬件钱包或 API 限权。
