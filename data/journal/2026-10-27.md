# 研究报告：加密货币跨交易所套利（Statistical Arbitrage）

## 背景
- **加密货币市场** 24/7 运行，流动性在不同交易所之间分布不均。
- **价格差**（Spread）在高波动时段会出现短暂的偏离，为套利提供机会。
- 常见的套利类型：
  1. **跨交易所现货套利**（买低卖高）。
  2. **跨品种套利**（例如 BTC/ETH 价差）。
  3. **期现套利**（现货与永续合约之间的价差）。

## 数据来源建议
| 数据类型 | 推荐 API / 数据源 | 说明 |
|----------|-------------------|------|
| 现货价格 | Binance, Coinbase Pro, Kraken, OKX | 提供深度、成交量、历史 K 线 |
| 永续合约价格 | Binance Futures, Bybit, FTX (已关闭) | 永续合约的标记价格与指数价格的差异 |
| 交易费用 | 各交易所公开的费率表 | 包括 maker/taker 手续费、提现费 |
| 跨链转账时间 | 各链官方文档 | 评估资金调度的延迟 |

## 套利模型概念

1. **价格差阈值**  
   - 计算同一资产在两个交易所的 **加权中位价**（考虑深度）。  
   - 当价差 > `threshold = fee_total + risk_buffer` 时触发套利。

2. **资金调度**  
   - 采用 **预置双向持仓**（在两个交易所同时持有等额资产），减少转账延迟导致的滑点风险。  
   - 若资金不足，可使用 **闪电贷**（如 Aave）进行瞬时放大交易。

3. **风险控制**  
   - **最大持仓比例**：不超过总资产的 30%。  
   - **单笔交易最大亏损**：设置止损为 0.5% 的预期利润。  
   - **监控网络拥堵**：在链拥堵时自动暂停套利。

# 套利概览

## 什么是跨交易所套利？

跨交易所套利（Cross‑Exchange Arbitrage）指在同一时间点上，利用不同交易所之间同一标的资产（如 BTC/USDT）报价的差异，低买高卖，从价差中获利。  
典型流程：

1. **获取实时买卖价**：从两个或多个交易所获取最优买价（Bid）和卖价（Ask）。
2. **计算价差**：  
   - 若 `Exchange A` 的 **Ask** 低于 `Exchange B` 的 **Bid**，则可以在 A 买入、在 B 卖出。  
   - 价差 = `Bid_B` - `Ask_A`.
3. **扣除费用**：考虑交易手续费、提现/转账费用以及网络延迟。只有当 **净价差 > 费用** 时才值得执行。
4. **执行**：通过 API 下单并在必要时转移资产（如跨链或跨平台转账）。

## 关键要点

| 要素 | 说明 |
|------|------|
| **交易所选择** | 需选流动性高、API 稳定、提现速度快的交易所（如 Binance、Kraken）。 |
| **手续费** | 现货交易一般为 0.1%~0.2%（maker/taker），提现费用视链而定。 |
| **延迟** | 价格快速变动，网络与下单延迟会导致套利机会消失。 |
| **资金分配** | 为避免转账时间成本，通常在每个交易所预留一定余额。 |
| **风险** | 市场波动、API 失效、提现冻结、对手方信用风险。 |

## 初步实现思路（Python + ccxt）

1. **配置交易所**：使用 `ccxt` 实例化 Binance 与 Kraken，设定交易对 `BTC/USDT`（Kraken 为 `BTC/USD`，需统一计价单位）。
2. **获取订单薄**：调用 `fetch_order_book`，提取最高买价 (`bid_price`) 与最低卖价 (`ask_price`)。
3. **计算套利**：  
   ```python
   spread = bid_kraken - ask_binance
   net_profit = spread - (fee_binance + fee_kraken + transfer_fee)
   ```
4. **阈值检测**：若 `net_profit` 大于设定阈值（如 0.2%），记录并发送信号（可写入 CSV 或推送到 Telegram）。
5. **循环监控**：每隔几秒执行一次，持续捕捉瞬时机会。

# 跨交易所套利最佳实践

1. **交易所选择**  
   - 选择流动性高、API 速率限制低、提现速度快的交易所（如 Binance、Kraken、Coinbase Pro）。  
   - 关注交易所对同一资产的报价差异幅度，一般需要 > 0.5% 才能覆盖手续费与转账成本。

2. **手续费与转账成本**  
   - 现货交易手续费：大多数交易所 0.1%–0.2% maker / 0.2%–0.3% taker。  
   - 转账费用：跨链转账费用（如 BTC 交易费）与提现手续费（如 USDT 0.5–1.0 USDT）。  
   - 计算净价差时需将所有成本合并。

3. **延迟与执行**  
   - 价格波动极快，延迟 > 1 秒就可能失去机会。  
   - 使用 WebSocket 订阅订单簿（如果交易所支持）可降低延迟。  
   - 订单执行时采用 **限价** 或 **市价** 取决于资金量与滑点容忍度。

4. **风险管理**  
   - **资金分配**：在每个交易所预留足够余额，避免因转账延迟导致资金锁定。  
   - **对手方风险**：若对方平台出现崩盘，订单可能无法成交。  
   - **监管风险**：不同地区对跨平台转账有不同监管要求，需保持合规。

5. **监控与日志**  
   - 每一次套利机会均写入 CSV 或数据库，方便回溯与性能评估。  
   - 记录时间戳、买卖价、价差、手续费、净利润、是否执行。  
   - 定期检查日志，评估策略有效性与成本结构。

6. **代码结构建议**  
   - `fetch_order_book` → `calculate_spread` → `compute_net_profit` → `log_result`。  
   - 用异常捕获保证脚本连续运行。  
   - 采用 `asyncio` 或多线程可进一步降低延迟。
